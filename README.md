# 浏览器自动化与 AI 招聘助手（dsh-ai-recruiter）

独立 DSH Host + Client 插件工程。可以只上传、复制或发布当前目录；源码、依赖锁、配置和发布脚本均在目录内，不依赖父目录或其他插件。

目标：薪灵 1.0.2，DSH/tools/system-prompt 0.1.6-alpha.1，Cordis 4.0.2。使用 Node 22.12 以上；建议使用薪灵内置 Node 24。保留当前宿主契约，不代表已兼容官方 DSH 0.2.x。

0.1.108 新增对话内插件调用卡片：通过 DSH 的 `tool.call.toolview` 插槽（按工具名 keyed）接管招聘插件 14 个工具的渲染，把工具名+JSON 结果变成可读摘要（查询命中、任务逐人结果、采集/入库进度、授权状态），失败显示错误码，「详情」跳到轨迹。

0.1.107 修正简历入库来源职位核验的无解条件：猎聘该筛选是 rc-select，可见文案在容器上、值在空的 search input 里，且语义快照可能不给 `collapsed`，原实现只检查被引用的单个元素因而无解。现接受容器形态、去掉 `collapsed` 硬要求（展开态仍拒绝）、控件证据优先，`task_confirm_source_position` 的 `ref` 改为可选。本轮依据真实页面只读快照修正，不再依赖推断。

0.1.106 修正与思考模式的契约冲突：宿主预设的执行结果此前被伪造成「只有 tool-call 的 assistant 轮次」，而思考模式要求带工具调用的 assistant 消息必须附回其 thinking，导致每轮在 turn 1 被 400 拒绝。现改为 user 轮次的「宿主事实」观察清单；真实模型轮次的 reasoning 仍原样回传。

0.1.105 修掉同一类参数事故的第二例：扩展快照始终带 `frameId`，预设却把它无条件带给 `browser_click`/`hover`/`scroll`，而这些工具未声明该字段，首屏后第一次点击必然被 `additionalProperties:false` 拒绝。同时不再吞掉模型失败的真实原因（`finish.kind=error` 会带出提供方 `code`/`status`/`message`），提供方失败同轮有界重试一次，取消不重试；`preset_paused` 新增 `failedDetail` 记录校验失败字段路径。

0.1.104 修正「预设每次都在 2 秒内交棒」的真正根因：预设给只读的 `browser_wait` 传了 `purpose`，被 `additionalProperties:false` 的 schema 拒绝，于是新开标签页首屏必定 `tool_failed` 交棒（旧版曾误判为职位核验过严）。同时只读工具改为剥离 `purpose` 防复发，模型流零 chunk 时同轮有界重试一次。

0.1.103 先解「走不通」再治「慢」：平台预设此前几乎立刻退出，把打招呼全程交给模型逐步试错（实测 7 分钟 0 人）。本版把职位核验从「必须拿到平台职位 ID」改为 `exact` / `degraded` 两级——降级要求目标名称唯一、页面唯一选中、且页面上没有可对照的职位 ID（有 ID 却对不上仍然拒绝）；同名多选项且无 ID 证据时立即停止并说明原因，不再空转；下拉触发器 hover 未展开时允许一次真实 click。止损侧：失败身份不再包含位置与状态，停滞连续 3 次即 `PRESET_NO_PROGRESS` 停止，并新增「已失败做法」账本。完整问题清单与后续阶段见 [提速与卡死治理路线图](docs/browser-agent-speedup-plan.md)。

0.1.102 打通两种入口：会话通过 `ai_recruit_task_options/start/status/stop` 提交统一后台任务，工作台按钮调用相同执行器。会话右侧自动打开精简招聘进度面板，按会话隔离任务，展示进度、逐人结果、执行动态、停止和复制日志，重新打开不重复执行。猎聘只对“立即沟通”进入预设点击路径，“继续沟通”禁止重复点击；点击成功直接记“已点击”，不再逐人等待发送证明或请求 AI 确认。仍保留 5 秒最小点击间隔、去重和未知结果停止。

工作台增加猎聘搜索人才模式：关键词、城市、年龄上限、工作经验范围先由任务内 AI 设置并核对已生效条件，再交回预设连续处理；无法准确设置时不忽略条件。简历入库增加独立且可选的平台列表职位筛选，沿收到简历、详情、附件下载、保存回执处理，已知简历弹窗通过关闭控件或 Escape 返回列表。文件完整性和最终保存确认不简化。

0.1.101 修复详情弹窗附件定位：按当前候选人的前景弹窗关联实际下载按钮，不把整个附件 section 当成下载控件。视口外控件先滚动并用新快照引用继续；模型观察保留控件坐标。保留真实遮挡、多个附件歧义、完整文件校验和未知入库不可重放边界。

0.1.100 修复 `ai_recruit_context` 的字符串参数兼容：`args` 优先使用 JSON 对象，也接受一次 JSON 编码的对象字符串。职位和人员查询统一在分发前解析，仍拒绝数组、null、标量、多次编码和不符合业务契约的参数；参数形状错误标记为 `CONTEXT_ARGUMENT_INVALID`，不表示浏览器连接异常。

插件现已包含 **AI 招聘工作台** 侧栏页面：选择平台和人数后一键自动打开推荐人才页并沟通，支持点击间至少 5 秒、每日额度、去重、实时进度与按候选人汇总的最终结果。安装后重启，在侧栏进入工作台。用法、当前页面适配范围与验收边界见 [工作台说明](docs/workbench.md)。

猎聘/BOSS 已知流程优先由招聘插件内的平台预设执行：选职位、识别候选人、打招呼和核对、打开简历、预览附件、采集入库及列表推进。正常路径不调用模型；职位、身份、入口或结果不明确时，把真实操作记录和最新观察交给 AI，恢复到可识别状态后自动继续预设。模型配置在需要 AI 时才读取。预设复用现有业务工具、真实引用和结果校验，发送记录、防重、5 秒间隔、未知结果停止、文件完整性和入库回执继续生效。平台规则集中于插件，薪招扩展仍提供通用浏览器能力。

0.1.99 按真实猎聘页面修正预设未命中：识别卡片开头的“在线”等状态，按同一卡片的父子关系和位置合并不同文本片段，保留独立同名卡片的歧义检查。页签选择、无页签时进入已知入口和最多五次短加载等待由代码完成；语义观察缺少职位 ID 时直接读取 DOM 核验。开发日志记录 `recruitment.preset_paused` 的具体原因，避免只看到切换 AI 而无法判断未命中环节。

最后一人的结果核实后，达到设置人数即由宿主结束任务，不再等待模型单独调用结束工具。结果变化优先与证据自身的唯一元素标识、上下文或位置匹配比较，不因别人的控件已有相同状态文字而拒绝本人的状态变化；无法区分的重复证据仍不当作成功。重复结果校验失败不能靠修改说明或引用绕过次数上限。

通用执行层要求将参数已知且无需解释中间结果的连续工具调用放在同一轮；动作默认返回新观察，部分 `observe` 参数会补齐默认快照，明确 `returnSnapshot=none` 时保留原意。每个标签页/框架只保留最新观察全文，旧观察和失败恢复观察转为摘要，操作回执与错误仍保留。性能机制与验证范围见 [性能说明](docs/browser-agent-performance.md)。

语义引用只读检查失败时返回新的 DOM 观察及新引用，由 AI 重新选择目标；原操作不自动重放。配套开发运行包将只读检查与写入身份核验分开，仍保留任务、标签页、文档及实际写入的身份约束。

真实点击返回遮挡错误时，在同轮恢复中只读检查失败目标及其祖先；若原观察是语义树且工具支持 DOM，改用一份新 DOM 观察，让 AI 区分文字节点、实际控件和页面遮挡。检查失败仍尝试返回新观察；不自动重放输入，不把祖先当作自动点击目标，未知写入不进入该恢复路径。

## 开发与打包

开发排障可使用工作台“复制开发日志”；日志目录、级别配置和字段说明见 [开发者日志](docs/developer-logs.md)。

在当前插件目录执行：

```bash
npm ci
npm run pack
```

`npm run pack` 生成 `artifacts/dsh-ai-recruiter-0.1.109.tgz`。普通 `npm pack` 也会自动编译。`src/lib/` 是当前插件私有的业务和基础代码，编译为 `dist/lib/`；无需另一个共享包。默认仅编译打包；本地回归可在构建后运行 `node --test test/*.test.mjs`，测试文件不进入安装包。

## 发布到 npm 或插件服务器

将整个当前目录作为独立工程上传到构建服务器，运行 `npm ci && npm run pack`；若服务器接受成品，上传 `artifacts/` 中的 tgz 即可。服务器运行时需满足 Node 版本要求。

确认包名、版本和目标 npm registry 后，在当前目录执行：

```bash
npm publish
```

发布前自动执行编译；npm 包内包含已编译代码和 bundle patch，不需要用户构建源码。当前工程没有执行 npm 发布。

## 用户安装与运营分发

面向用户的安装流程见 [用户安装指南](docs/user-installation.md)。用户通过兼容客户端的插件管理入口，使用运营方发布的 npm 包版本或 HTTPS tgz 地址安装。插件自带已编译代码、网关和 Skill；用户无需源码、Python、npm 或额外安装网关。

插件首次加载自动初始化并注册本机原生桥接；固定 ID 的扩展后台取得配置，用户直接提出浏览器任务即可。网关复用宿主 Node，按需启动。无业务账号、配对链接或文件导入要求；异常时保留备用入口。实现说明见 [本机自动连接](docs/native-connection.md)。

开发机上的 scripts/xinling-dsh.py 和 scripts/install-ai-recruiter.py 仅用于开发调试，不是客户安装依赖。当前版本尚未发布到 npm 或统一插件服务器，扩展正式分发地址也尚未配置，不能将本地 artifacts 路径当成客户链接。

## 浏览器与入库前置条件

发布包内已包含本地网关，默认使用包内 MCP 入口，不依赖 xinzhao 源码、全局 Skill 或外置网关目录。需要包含 Native Messaging 自动连接和 artifact.read 能力的新版薪招扩展。

`ai_recruit_help` 中 `browser.available=true` 只表示 MCP 工具可发现，`browser.ready=true` 才表示网关和扩展已连接。简历入库另需宿主提供 `xrxsAuth`（通常来自 `xrxs-dsh-auth`），并调用 `ai_recruit_auth_check` 确认 `authenticated=true` 与 `recruitmentReady=true`。鉴权说明见 `docs/authentication.md`。

0.1.83 的工作台打招呼、简历页面决策及登录检测回退使用宿主 `llm` 与 `agentDefaultModel`：复用薪灵模型设置中的默认模型和宿主凭据，打招呼与简历执行器使用原生工具调用和任务内连续上下文，无需单独填写模型密钥。模型可按需检查局部 DOM/样式/ARIA 关联、读取 Chrome 无障碍树、查看网络请求状态，再刷新快照并选择动作。模型判断职位切换、候选人、附件、弹窗、翻页和加载状态，并通过通用悬停、点击、输入、按键、下拉选择、后退和 iframe 观察完成页面操作；代码核验引用与身份/职位证据，负责额度、节奏、去重、文件传输及入库回执。下拉触发器可通过 hover 展开并在新快照中选择；相同页面状态下的重复动作会被拦截，包含菜单来回开关的循环。上传渠道从主系统当前公司启用列表读取。授权及主系统预上传、提交实现保留。需要配套薪招扩展 3.2.39+ 的 `mode=download`，在监听文件响应后真实点击下载；扩展源码独立维护于薪招工程，DSH 包运行时不依赖它的源码目录。

## 随插件启用的 Skill

包内 `skills/xinzhao-browser-control/SKILL.md` 在插件挂载时注册到 DSH Skill 服务，支持模型自动选择和用户显式调用；无需另装全局 Skill，卸载插件时自动撤销注册。技能正文通过宿主的 `skill` 工具按需加载，指导模型何时使用薪招、如何发现和调用 `ai_recruit_*` 工具，以及何时释放浏览器执行权。单纯发现或加载技能不会唤醒浏览器。

插件声明 `skills` 服务依赖（目标薪灵/DSH 默认提供），并固定对应 `@deepseek-ai/dsh-skill` peer 版本。同名技能遵循 DSH 的作用域与优先级规则：同层注册时内置运行时技能优先于用户文件技能，Agent preset 或项目作用域的同名技能可能覆盖全局注册。已有自定义技能不会被复制覆盖或删除。卸载插件后已有全局技能继续保留。

该 Skill 是插件工具版本，不调用外置 Skill 的 CLI。浏览器扩展和本机配对仍是运行前置条件；网关由发布包提供。内置操作指引不会自动安装 Chrome 扩展。

## 首次配对与网关启动

普通用户安装后直接使用；后台自动初始化、发现和连接。以下命令和文件导入只供开发维护、旧扩展兼容与排障使用：

```bash
node browser-agent-gateway/manage.cjs setup
```

发布到 npm 后，用户也可以通过发布版本执行：

```bash
npx --yes --package=dsh-ai-recruiter@0.1.30 dsh-ai-recruiter-browser setup
```

命令在 `~/.xinzhao/browser-agent.local.json` 保存随机的本机配对，文件权限为 0600；再次执行保留已有配置，不更换凭据，不启动浏览器或网关。打开 Chrome 薪招扩展设置，在「本地浏览器连接」中导入该文件，结束已有浏览器任务后重新加载扩展。如果此前运行过开发网关，应先结束任务并退出旧网关，避免旧进程继续使用另一份配对。此入口需要使用本次更新后的薪招扩展；旧版本应先升级。手动导入的配对优先于构建时的开发配置，升级后仍保留。

已有开发机配对可以迁移，命令只取 `localGateway`，不复制远端凭据：

```bash
node browser-agent-gateway/manage.cjs setup --import /absolute/path/to/config/browser-agent.local.json
```

已有用户目录配对时保留原文件；需要更换配对时先结束任务、退出旧网关，再自行备份并移走原文件。可以在首次 setup 时用 `--port 5031` 指定其他端口。

检查本机状态、启动并等待连接：

```bash
node browser-agent-gateway/manage.cjs doctor
node browser-agent-gateway/manage.cjs ensure
```

`doctor` 只读检查并隐藏凭据；`ensure` 按需启动、等待扩展连接。DSH 内通过 `ai_recruit_browser_call` 调用发现的 `browser_ensure` 或浏览器工具也会按需启动。Skill 加载、工具发现、help 和 doctor 均不启动浏览器网关；browser_setup 会创建五分钟的本机配对服务。未配对时明确返回 `XINZHAO_LOCAL_PAIRING_REQUIRED`，不会使用开发默认 token。

浏览器操作结束调用 `browser_finish` 释放执行权。网关无人调用 15 分钟后退出，下次调用重新启动；插件卸载撤销工具和 Skill，保留用户配对及本地记录。

`XINZHAO_GATEWAY_CONFIG` 可指定另一份本机配置。`browserMcpArgs` 和 `XINZHAO_GATEWAY_MCP` 用于显式选择外置 MCP；默认始终使用包内网关，显式选择无效入口时报告错误，不回退到开发机源码。网关、CLI、MCP 和开发脚本统一在当前工程维护，xinzhao 中的旧网关目录已迁出。`browser-agent-gateway/UPSTREAM.json` 只保留迁移前的来源摘要，不表示还有另一份上游实现。构建过程中不读取外部工程或复制本机配置。
