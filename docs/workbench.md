## 页面理解与执行边界

用户描述的猎聘三条操作流程见 [猎聘招聘操作规范](liepin-workflows.md)，双入口和会话面板见 [统一入口说明](recruitment-entrypoints.md)。源码接入不等于已完成真实页面或客户端验收。

猎聘/BOSS 已知流程优先使用招聘插件内的平台预设，按当前快照识别职位、单人候选人、默认招呼与完成状态、预览及下载入口，直接执行后继续观察。预设匹配的正常路径不调用模型；身份信息不足、职位或结果无法确认、陌生前景及普通工具失败时才初始化宿主模型，将真实工具记录、错误、当前候选人和最新观察交给 AI。AI 处理后，每轮推理前再次匹配预设；页面已恢复时直接接回快速路径。平台预设位于插件，扩展保持通用浏览器能力。

启动时优先读取所选页签或唯一匹配任务路径的已有页签，必要时使用唯一活动平台页签；存在多个无法消歧的匹配页签时交给 AI，不任意替换。没有平台页签时直接进入预设入口。首屏尚未加载时，最多五次短等待并重新观察，再决定是否需要 AI。猎聘卡片的“在线”前缀不作为姓名；同一卡片的完整履历、局部履历及招呼按钮通过位置和层级关联，不要求文本完全一致，独立同名卡片仍需消歧。

通用页面能力包括悬停（hover）、点击、输入、按键、下拉选择、滚动、等待、后退、切换已观察标签页、观察已列出 iframe、导航到已观察且属于所选平台的 URL。跳转后重新读取快照；模型不能编造引用、地址或业务 ID。代码检查快照引用、可用状态、所属平台和候选人关联证据；打招呼还核验当前职位的原文及选中状态/已关联平台职位 ID。

预设按平台入口、控件文案、卡片关联、唯一身份及当前选中职位工作；遇到歧义交给模型，不把未匹配当作没有候选人。发送次数、间隔、去重、写前记录、文件传输、接口回执及未知结果停止由原有业务工具控制。预设与模型都不能绕过这些工具，不能付费、批量开聊或修改任务范围外的业务数据。页面适配及模型理解仍需真实页面验收。

需要具备 `mode=download` 的配套薪招扩展。正常预设路径不要求模型服务；需要 AI 时才读取模型配置，缺失时明确停止并保留已有记录。模型每轮最长 90 秒；普通失败交回同一工具对话，重复失败及任务总预算有界。未知浏览器执行、未知入库和持久化失败立即停止，不交给 AI 重试。动作始终使用真实引用，输入前仍检查文档、身份和当前命中。

AI 使用实际 MCP 工具的原生对话，同一任务保留完整调用及结果组，按组裁剪历史上下文。参数已知且不依赖新观察的调用可同轮顺序执行；相邻独立只读工具最多三个并发，会替换引用的观察和页面输入仍顺序执行。输入默认返回新观察；过期引用的只读恢复不重放原输入。详情见 [性能说明](browser-agent-performance.md)。

局部检查返回控件与祖先、关联隐藏菜单、允许属性的 HTML 和计算样式，过滤脚本、密码/隐藏输入、任意 data 属性；隐藏菜单内容不带可操作引用。真实 AX 树用于结构理解，动作仍使用 DOM snapshot ref。网络检查首次才开始监听，只给本任务允许域名的请求路径、方法、状态，不读取头、请求体或响应正文。没有开放任意页面 JS 来绕过业务回执。

DOM snapshot 保留 parentRef、tagName、controls、hasPopup 和非密码控件值。操作回执保留 dispatched/changed、控件前后状态、滚动位置和验证结果；页面变化不代表职位已选中或消息送达。可视遮罩始终 pointer-events:none，通过 window 捕获阶段的输入门禁保护点击/按键，不拦截悬停移动，防止鼠标移入后菜单被遮罩关闭。

0.1.81 补齐 `hover`：不确定触发方式的下拉/更多控件先悬停观察，指针停留后读取新快照，从展开的选项选择目标，不再反复点击触发器。打招呼与简历执行器共用该能力，平台交互仍由模型判断。

通用导航记录目标引用/角色/标识、简短理由，以及下一份快照中观察到的状态变化，作为 recentActions 交回模型。相同状态下的同一动作最多执行两次，第三次在调用网关前阻止；菜单 A→B→A 循环同样累计，快照/ref 更新或改写理由不能绕过。仅确认处理完一个候选人后清理导航计数。纯等待不受两次限制，仍受任务总操作预算约束。连续三次引用/重复拦截错误停止；此保护不会重试未知执行，也不代替写入防重。

页面状态指纹来自当前模型可见的 URL、文字、元素及状态、选中标签、弹窗和标签页，排除快照 ID 与元素 ref，不只比较元素数量。动态页面变化不必然表示任务推进，仍需模型核对目标职位与候选人。

开发日志记录 `greeting/resume/login.model_decision`、模型失败/未完成、实际动作、ref、耗时与 token 用量，不保存提示词、完整模型回复、推理或简历正文。任务详情显示简短操作原因；接口日志说明见 [开发者日志](developer-logs.md)。

## 打招呼

1. 选择猎聘或 BOSS 直聘、薪人薪事职位及人数（1–100），确认后开始。
2. 预设核验当前职位，必要时从唯一可确认的平台职位选项切换。存在关联时核验真实目标平台职位 ID，展开的未选中选项不能当作当前职位。无法确认时交给 AI。
3. 预设从当前页面识别单人卡片及默认招呼入口，姓名和身份信息不足或同名歧义时交给 AI；模型选人不受预设的年龄、学历格式限制。身份原文、资料链接和历史去重沿用原有工具。
4. 点击前保存 `sending`，收到已识别单人招呼按钮的成功点击回执后自动记为“已点击”，清空当前候选人并进入下一人，不调用模型核实发送结果、不伪造 `confirmedAt`。猎聘预设只点“立即沟通”，“继续沟通”禁止点击。点击失败不计成功，未知执行保存 `unknown` 并停止，跨任务和重启不自动重发。
5. 每次打招呼点击之间至少 5 秒。定位下一人和必要观察在间隔内完成，仅补足剩余时间；正常点击不等待 DOM 安静或发送成功提示。最后一位点击完成、达到设置人数后由宿主结束，不再单独请求模型。

猎聘可选择“搜索人才并筛选”，填写关键词及可选城市、年龄和经验范围。任务内 AI 只负责设置条件和引用实际生效证据，确认后预设连续执行；推荐模式不会代替搜索模式。简历入库的平台职位筛选独立于薪人薪事目标职位，仅保留给会话任务的可选参数 `platformJobName`；工作台表单不再展示该字段，默认按全部职位处理。

本机默认每个平台按北京时间自然日累计最多 100 次尝试；未知结果也占额度，跳过不占额度。仅统计本工作台，平台其他渠道的额度以平台提示为准。工作台固定每次打招呼点击之间至少 5 秒，不再随机等待或分组暂停。模型处理超过 5 秒时立即继续，不额外再等 5 秒。`greetingDailyLimit` 默认 100；旧间隔、分组配置字段仅保留兼容，不再控制当前工作台的节奏。

全部记录展示每位候选人的最终结果；同一候选人先失败后成功，仅保留成功结果用于展示。历史尝试原数据不删除，独立可确认的同名候选人不会强行合并。列表条数、成功人数和最近任务计数使用同一汇总口径。

登录或验证由用户在浏览器处理，模型可等待最多三分钟后停止。平台额度不足、职位或候选人无法可靠对应时停止。

## 登录状态

保留 `browser_channel_login` 的后台渠道会话检测，不调用模型。旧扩展或渠道接口不可用时，复用已有平台标签页读取快照，由模型给出登录状态及页面原文证据；证据缺失或页面不一致时为 unknown。平台明确标记为登录页时判未登录。只关闭检测过程自建且无须展示的标签页，保留用户原有页面。

## 批量简历入库

选择招聘平台、薪人薪事目标职位及数量（1–50）；来源渠道、投递类型、上传位置收在「高级选项」中，默认只展示当前选择。目标职位只保留下拉选择，同名职位显示编号。启动时重新读取真实选项及权限。

| 表单字段 | 接口参数 | 选项来源及默认值 |
| --- | --- | --- |
| 目标职位 | `jobId` | 当前账号在招职位，必选 |
| 来源渠道 | `channelType` | `ajax-get-channel-list-setting?status=0` 中 `openStatus=0` 的真实渠道，并固定提供「默认渠道」0 作为第一项和默认值；接口已返回 0 时不重复添加 |
| 内推人 | `recommenderId` | 渠道 20 必填 |
| 猎头供应商 | `headhunterSupplierId` | 渠道 34 必填 |
| 投递类型 | `deliveryType` | 被动 1（默认）/ 主动 0；与招募前端 `deliveryTypeList` 一致 |
| 上传位置 | `resumeLibrary` + `resumeLibraryStatus` | 新简历 · 未处理 1-10（默认）/ 待定 1-11 / 当前账号有权限的人才库分类 4-{分类ID} |

渠道列表无效或读取失败时显示错误，不回退硬编码渠道；支持企业自定义渠道。内推、猎头的身份前置条件由代码校验，其他渠道不发送这些字段。聊天工具 `ai_recruit_destinations` 同样返回真实启用渠道及入库位置。

任务进入平台已收简历页面后，预设逐人识别候选人、打开详情与预览、定位原始附件下载入口，复用原采集入库工具。已有成功、失败或待核实记录继续按原规则处理。预设身份信息不足、页面变化或附件入口不明确时，交给 AI 理解；恢复已知页面后继续直接执行。

最终下载动作交给宿主：先监听文件响应，再真实点击并捕获文件。HTML/JSON 等非附件拒绝上传，连同最新快照与原因交给模型选择其他明确入口；同一失败入口不原样重试。无附件的在线简历不在当前采集范围内。

0.1.79 已验证的授权及上传链路保留：扩展 artifact → Host 内存读取分片 → 文件服务取得 `fileKey` → `ajax-add-preupload-resume` 取得解析缓存标识 → `ajax-submit-upload-resume` 提交。两个业务接口继续使用授权返回的 `systemURL` 和现有系统会话，不使用 CLI 上传接口或另外获取 OAuth token。`resumeFileKeys` 由代码按回执组装，预上传标识不显示为最终简历编号，只有最终提交明确成功才记入库成功。

逐人提交用于将回执对应到候选人。未知写入立即停止、保留检查点、不自动重放；历史 saved/unknown 参与后续去重。文件服务上传、解析、提交、保存分别显示进度。批次全部投递到用户选择的目标职位，不自动猜测职位映射；原始文件不落盘。

## 开发与验收

`npm run build` 编译 Host 与 DSH Client；构建后可执行 `node --test test/*.test.mjs` 做本地替身回归。`npm run pack` 生成 `artifacts/dsh-ai-recruiter-0.1.102.tgz`，安装到 desktop profile 后完全退出并重新打开薪灵加载。

本版的编译、打包及替身回归不证明模型在真实登录页面中的选择正确，也不证明消息送达或真实入库成功；平台页面与业务端到端验收由实际使用完成。任务取消、重启或异常退出不会自动恢复未知写入。

新增功能沿用 `WorkbenchTaskExecutor`，在 Host 初始化时注册独立存储前缀，Client 参数表单登记到 `TASK_FORMS`；类型在 `src/shared/workbench.ts` 声明。后台任务、聊天浏览器调用共用互斥锁。

0.1.83 修复可选候选人资料元素无真实链接时的误拦截：姓名、身份原文及候选人关联核验通过后，可按文本身份去重；无效或站外 URL 会反馈具体原因给模型修正。已有成功、发送中和未知结果仍禁止重复发送。
