# BOSS 直聘 AI 操作最佳路径

本文件说明 BOSS 的寻聘与简历入库路径。提示词与平台元数据的唯一事实源是
[`src/lib/platforms/boss/ai-route.ts`](../src/lib/platforms/boss/ai-route.ts) 和
[`src/lib/platforms/boss/definition.ts`](../src/lib/platforms/boss/definition.ts)；
本文件只解释原因和边界。

## 为什么不能复用猎聘的路径

通用提示词按猎聘写成「顶部大搜索框/职位下拉 → 姓名链接 → 在线简历 → 打招呼」。
BOSS 的推荐列表通常嵌在同源 iframe 内。姓名节点本身未必可点击，
点击所属卡片主体才能打开简历详情；正文可能在新的 Canvas iframe 中，不能依靠列表文字读取。

| 维度 | 猎聘 | BOSS |
| --- | --- | --- |
| 寻聘入口 | 人才推荐/搜索 | 左侧「推荐牛人」 |
| 职位选择 | 顶部大搜索框最左侧「不限职位」 | 顶部「职位名 _ 城市 薪资」招聘职位下拉 |
| 候选人履历 | 姓名链接打开在线简历 | 卡片主体打开详情；DOM 正文或 Canvas 图片正文 |
| 寻聘动作 | 读在线简历、评分、再招呼 | 列表初筛 → 打开真实详情 → 完整读取、评分、保存 → 返回原卡招呼 |
| 已收简历 | 人才管理 → 收到简历 | 沟通 → 已获取简历 |
| 入库附件 | 收到简历列表内下载 | 已获取简历列表/聊天详情内下载 |

## 寻聘路径

1. **进入推荐页**：`https://www.zhipin.com/web/chat/recommend`，左侧点「推荐牛人」。
   列表若在同源 iframe `web/frame/recommend`，用 `browser_list_frames` 找到并在原页面中读取和操作；
   不得把 iframe 地址导航到顶层或拼接端口；
   BOSS 没有可用的主动人才搜索入口，不要转搜索。
2. **选择职位**：顶部右侧显示「职位名 _ 城市 薪资」并带下拉箭头的控件是**招聘职位下拉**。
   点击后按 `platformJobs` 的名称/业务 ID 选择目标职位，选中后核对顶部显示和当前列表。
   同名歧义或 ID 冲突时停止，不能猜；URL `jobid` 只用于复核同一文档。
3. **列表初筛**：卡片是 `li.card-item > .candidate-card-wrap > .card-inner`。
   姓名是 `span.name`，不是链接；卡片最完整的原文是同卡「打招呼」按钮的 `context.text`，
   含姓名、薪资、年龄、经验、学历、期望、优势、工作经历和教育经历。
   无真实简历 ID 或链接时，使用经核验的完整单人卡片文本生成去重键，剔除末尾招呼按钮与活跃状态；
   「打招呼」变为「继续沟通」不能形成新人。旧格式键保留为别名，招呼回执保持原样；不能只按姓名合并。
4. **读取详情**：列表初筛通过后，inspect 姓名所属的 `.card-inner`，核实其位于
   `.candidate-card-wrap` 内，再点击一次主体。必须观察到真实详情；列表不变时不能宣称已读简历。
   正文若位于 `web/frame/c-resume` 的 Canvas，按滚动位置分段截取，覆盖顶部至末尾后交给
   支持图片的模型逐字转写；长简历按批识别，每批最多 8 张图片，后续批携带首图独立核验姓名，
   全部批次成功后合并正文。右侧「经历概览」仍是摘要，不能作为详情保存。
   当前任务已绑定的详情若未完整采集或识别，关闭并跳过本候选人，继续下一位；连续 3 位失败停止。
   姓名不符、图片能力缺失或操作结果未知仍须停止核验。
5. **评分和保存**：只用详情正文评估；保存前复核当前详情及图片证据，记录图片摘要哈希。
   详情已确认读取后才显示「已读取简历详情 N 字」，并注明图片识别来源。
6. **打招呼**：评分达标且宿主返回 `needsGreeting` 后，核验详情关闭控件，关闭并回到原卡，点该卡唯一的
   「打招呼/立即沟通/立即打招呼/聊一聊」，核对点击回执后继续。
   点击结果未知时停止核对，不重发招呼。
7. **推进**：「下一页」或滚动；只有真实「没有更多/暂无…/已到最后」提示才可
   `sourcing_finish(completed)`。连续两次推进 `sourceId` 集合不变即停止。
   付费/认证/权益阻碍用 `sourcing_finish(status=stopped, reason=具体阻碍)`。

## 简历入库路径

1. 左侧「沟通」→ `https://www.zhipin.com/web/chat/index`。
2. 切到「已获取简历」tab（不在「人才管理」，也不在「推荐牛人」）。
3. 按姓名 + 平台身份/聊天记录/附件上下文选择当前候选人；同名不能只按姓名合并。
4. 打开该人的简历或聊天详情，找到与本人关联的真实附件下载控件，
   用 `task_import_attachment` 提交；附件区块、预览区、简历容器都不是下载按钮。
5. 列表滚动或翻页推进；没有更多已收简历时用 `task_finish` 说明。

## 代码落点

- `BossResumeDriver`：打开已核验卡片主体，等待真实详情，绑定候选人与详情文档；返回时核验并关闭弹窗。
- `bossPlatform.readResume`：读取已绑定的 Canvas 详情，禁止未关联所选候选人的图片进入评分。
- `visualResumeReader`：分段覆盖、图片转写、姓名校验及保存前图片复核；正文按 `online` 保存，
  同时保留图片证据摘要。宿主附件服务向模型传入真正的图片消息。
- `bossDefinition.receivedTab = '已获取简历'`，
  `receivedResumes = { receivedPath: '/web/chat/index', requiredTab: '已获取简历' }`。
- `runResumeAgent` 的平台说明来自 `receivedResumes.guidance`，BOSS 不再收到
  「猎聘从人才管理的收到简历 tab 处理」这段文字。

## 边界

- 列表卡片只用于初筛；详情正文用于寻聘评分。简历入库仍以真实附件和最终保存成功为准。
- 不购买权益、不索要联系方式、不下载未授权文件、不修改平台或主系统数据。
- 0.1.201 对触发 `RESUME_IMAGE_INCOMPLETE` 的同一份 6778 像素长简历完成实账号验证：
  卡片主体打开详情、采集 12 段图片、分两批由当前 DeepSeek 模型识别，取得 6385 字正文并关闭详情。
  此次验证未保存候选人或发送招呼，完整实账号寻聘任务仍待验收。
