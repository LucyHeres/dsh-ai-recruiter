同一任务保留连续的模型调用及全部工具回执。Agent 直接接收 MCP 提供的实际工具 schema，自主观察和选择动作，不经过业务 action 枚举。新工具定义可以直接注册；模型、服务商和推理档位沿用宿主选择，没有偷偷降档。

普通工具异常、参数错误及业务证据错误作为工具回执返回模型；未开始的后续调用跳过，模型根据新观察重新规划。没有按网站、弹窗样式、按钮名称、hover 场景分别编写恢复分支，也不再用三次普通恢复错误直接终止任务。任务仍有整体时间、轮数、上下文预算，取消、记录无法保存及未知写入会停止。

相邻独立只读工具最多三个并发；网页写入、任务记录和会替换引用缓存的观察工具按顺序执行。相互依赖的操作必须等前一步输出，不能盲目批量运行。成功结束由宿主任务条件决定，普通文字不能伪造完成。

## 业务与网页的边界

打招呼适配器只负责授权目标、选人证据、去重、人数、发送间隔、派发前落盘和结果记录。点击之间固定至少 5 秒，以点击回执为保守计时基准；确认/模型耗时计入间隔，不随机等待、不分组暂停，等待结束后直接进入实时引用检查。结果列表按候选人汇总最终状态，历史尝试不删除；同一稳定身份的重试直接更新记录。`task_select_candidate` 只建立记录；之后网页交互直接调用真实浏览器工具，可能提交招呼的操作必须声明 `purpose=business_write`。同一候选人的后续交互沿用当前记录，不自动把一次点击当成成功。页面和附件中的内容不能改写任务授权。

结果通过 `task_report_result` 记录 completed / not_completed / unknown。可引用当前控件的 `ref`、前景文字的 `dialogs.evidenceRef` 或页面正文的 `textEvidenceRef`。可读证据和可点击控件是不同概念：没有交互节点的状态文字也可引用；背景/disabled 内容可阅读，但动作仍需通过实时可达性检查。结果需要新观察，未变化的证据不能算完成。错误回执指出可用证据源，交回模型纠正，宿主不代替模型解释网页业务含义。

简历适配器只提供选人、导入真实附件、跳过和结束等业务 hooks。寻找附件、打开/返回、切页和恢复仍由同一个 Agent 处理。原 `RecruitEngine` 完整文件校验、上传、业务授权、查重和提交逻辑保留，Agent 的截止信号贯穿文件与上传流程，不允许用页面文字代替附件或未知入库重放。

实际写入回执包含 requestedTarget、实际 target、hitTarget 和 point；日志仅保存标签摘要、角色和坐标。写入已成功后若本地观察处理失败，也按未知写停止。只读观察的超时不等于新增业务写入未知，可以继续观察，同时保留已有发送记录。浏览器执行权仍由宿主管理，模型不能调用 begin/finish 抢占或释放其他会话。

## 观察与引用

`agent-browser-tools.ts` 动态装配工具、校验 schema、固定授权域名/确认信息和 documentId，并缓存任务内完整观察。每个 tab 的动作只接受其最新 snapshot/ref。扩展在快照时保存局部AX身份与选中职位哈希，首次检查及动作前均比对原基线，防止列表复用同一后端节点时把新候选人当成旧人。DOM引用也校验快照时的内容、上下文和文档。具有可区分局部上下文的引用最多保留10分钟，缺少此基线的引用仍为30秒；这不是放宽目标身份检查。扩展继续核对 task/tab/document、实际目标和前景遮挡；不能穿过真实弹窗点击背景。

语义快照使用 AX 树和 backend DOM 节点；发现前景时整体采用 DOM 观察，不混合两套引用。覆盖信息与分页入口明确返回。模型可用 `browser_read_observation(offset,limit,query)` 续读宿主完整观察，或用 `browser_snapshot(offset,maxItems)` 获取源端后续片段；后者产生新引用。没有显示完整不等于不存在。

模型观察使用一份语义树和去重上下文，避免同一元素以多个结构重复发送。不再每步强制重新列 tabs、列 frames、取 snapshot；何时观察由 Agent 决定。扩展自身遮罩仅在命中测量时临时让出，真正网站遮挡仍会阻止动作。
