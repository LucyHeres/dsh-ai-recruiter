# 人才寻聘（0.1.123）

工作台首页是「职位管理」，通过现有薪人薪事授权读取在招职位。每条满宽职位行按列对齐显示名称、部门、城市、职位编号，以及本插件记录的达标人才、已打招呼、已获取在线履历和已入库简历数量。统计按职位 ID 隔离；同一人的达标采集和招呼记录去重，不按相同职位名称合并。

点击「去招聘」进入职位招聘页。左上返回职位管理，标题为当前职位；下方依次是寻聘进度、人才列表。浏览器扩展入口始终带底色，任务记录统一收在顶部抽屉。

## 开始与设置

- 寻聘进度可展开或收起，已结束任务默认收起，运行中自动展开；开始、新一轮、寻聘设置与运行中的停止按钮常显。
- 设置自动读取当前职位 JD，支持编辑职位描述、本轮补充要求、猎聘/BOSS 多选及每个平台 1–100 人目标数量；「自动打招呼」开关默认开启，可手动关闭。
- 开始使用当前页面设置；没有可用 JD 或参数无效时先打开设置补全。运行中可查看设置，不能修改或重复启动。
- 渠道沿用当前浏览器登录会话，实际提交关键词并核验搜索结果；认证或权限不足时说明原因，保留已完成结果。

## 列表初筛与详情评分

要求提炼与独立简历评估主动加载随包的 `recruitment-matching` Skill。新轮次最多24项，区分硬性条件、核心能力、加分项和面试核实项：仅核心能力权重合计100，加分总权重不超过10；硬性条件和面试核实项权重为0。每段补充要求必须映射到实际标准或初筛条件，无法评估时保留可见原因；优先项不能作为硬过滤。相同要求复用同版本标准，规则升级不复用旧缓存；历史无分层标准的结果保留原分数。

模型读取每项完整要求原文，按实际职责、项目和成果做语义判断；基本功类要求先跨项目查找本人设计、实现、优化等行为，不能因未出现术语而直接判未知，具体实现工作可直接支持相关基础能力，可选多个当前人选的编号证据，并区分直接/间接证据、置信度和核实问题。宿主核验所有引文后计分：直接符合取全部权重，部分符合或间接推断最多取一半；核心未知项排除在已评估权重分母之外，同时显示核心证据覆盖率。核心覆盖不足70%或硬性条件未证实的人选直接跳过，不保存为待核实候选人；明确硬性冲突不通过。只保存达到本轮分数门槛且证据充分的人选，开启自动打招呼时立即跟进。单项材料未说明及面试问题作为分析信息保留，不单独阻止达标人选跟进。加分只奖励优势，不扣基础分；面试核实项不影响分数；总分封顶100。不使用性别、年龄、婚育、照片等详情评分维度。

列表初筛单独提取 JD 和本轮补充要求明确提到的六类硬条件：年龄、学历、工作经验年限、期望工作城市、工作经历就职公司和薪资。未要求的维度不参与；按符合项数/要求项数计算符合率，必须全部完全符合才打开详情，任一项不符或缺少列表证据都跳过。没有此类要求时直接进入详情评估。列表初筛不使用技能权重或最低匹配分；只有通过的当前人选可打开详情，不能借一人的授权读取其他人。详细评估分数不足本轮 minimumScore（默认60分）的已评估人选不保存、不执行招呼；重要信息不足的待核实人选单独保留，不占名额。进度仅保存宿主核验的执行节点，拒绝人选的身份和模型分析不会写入执行动态。

未知项是缺少证据，不代表确认不具备；列表阶段只会因明确要求的基本条件无法核验而跳过，不因技能或项目经历未展示而扣分。匹配分是当前职位的辅助筛选意见，不代表录用概率或通用能力。

## 自动打招呼

开启后，每位最终达到 60 分且保存的人选，需要先核验当前页面的候选人身份、真实主页链接或身份原文指纹、平台当前选中职位，以及本地历史招呼记录，才能点击平台默认单人招呼按钮。模型不能直接通过通用浏览器工具绕过宿主发送。

沿用统一浏览器锁、每日平台额度和至少 5 秒点击间隔；既有独立招呼任务与寻聘中的招呼记录共同参与去重和限额。已沟通过的人不重复发送；不存在可靠身份或职位证据时停止，不猜测。禁止自定义消息、群发、付费、索要简历或交换联系方式。

每个招呼的派发时间在点击之前落盘，实际输入回执返回后才记录「已点击」。超时、断线、取消或进程中断后的未知结果不重试，需到平台核对；明确尚未派发的页面错误可重新观察。最后一人达到采集目标后，仍须处理其招呼状态，不能提前宣告任务完成。

寻聘进度展示扫描、达标、跳过、已打招呼人数；沟通情况统一为「已打招呼 / 未打招呼」，没有招呼待确认状态。「已打招呼」表示存在真实点击或平台已沟通证据，不代表消息送达或对方回复。中断时保留底层执行回执防止重发，界面显示已停止。

「已收到简历 / 未收到简历」独立于打招呼。人才列表的「同步沟通状态」通过固定平台路径自动读取聊天或收到简历列表，不调用模型、不发送消息、不索要或下载简历。按平台简历 ID、候选人 ID 或已观察到的主页链接匹配本职位人选，同名不合并；猎聘的收到简历列表和已选中的「我发起的」「有简历」视图可提供对应事实。收到简历时间保存首次读取到接收记录的时间。在线履历采集、详情评分、导入主系统均不算收到简历。

同步沿用浏览器执行锁，每个平台每种列表最多读取 12 屏，总时限 2 分钟，结束后返回原页面。未匹配、列表不完整或登录失败时保留已有肯定记录；「未收到简历」表示尚无匹配的接收记录，不据此声称平台完整历史中一定没有。BOSS 与猎聘均有读取路径，本地回归覆盖匹配和限制；猎聘现有接收记录已在隔离测试存储中完成正向匹配，未向平台发送消息，BOSS 实账号接收记录仍需验收。

## 人才列表与历史

默认汇总当前职位所有轮次的达标结果，同一平台身份仅展示最新的达标评估。标题与筛选共用一个工具栏，左侧按分值、招呼情况、简历接收和平台组合筛选，右侧预设分数高低、发现时间、信息完整度排序，不再提供轮次筛选或收藏功能。

卡片显示基本信息、姓名右侧的平台标签、招呼状态和百分制分数。详情按所属轮次读取当时的职位要求、分析证据和已读原文，不把新旧标准拼接。桌面名单与详情独立滚动，窄窗口在名单和详情间切换。任务记录中仍可选择历史寻聘任务，查看那轮的评估；原始历史数据不删除。

列表接口只传基本信息和分数，选中后单独读取原文。在线履历由经身份核验的前景内容或弹窗原文组成，跨滚动累积，最多保留 30,000 字符并标注截断，不声称取得附件。没有链接时的原文指纹去重可能受卡片文案变化影响，不按相同姓名合并不同人或跨平台身份。

## 简历入库

职位页右上角「简历入库」打开独立抽屉，默认绑定当前薪人薪事职位。按原流程从平台已收简历列表获取附件，再上传至所选渠道和入库位置；来源渠道、投递类型、上传位置仍在高级选项。提交后打开实时入库进度，关闭后也能从顶部任务记录返回。它与寻聘共用执行锁，不能并发操作浏览器。

本版不自动向候选人索要简历，不把在线履历当作附件上传；暂未做逐位候选人与已收附件的跨流程关联。

## 数据和验证边界

数据沿用公司范围与 Store 私有文件权限，候选履历不进入开发日志。聊天入口仍可通过 `ai_recruit_task_options(kind=talent_sourcing)` 和 `ai_recruit_task_start` 使用同一执行器；`autoGreet` 默认 false，只有用户明确要求时才开启。

构建、模拟浏览器回归和实际前端组件的示例数据交互检查覆盖职位隔离、评分门槛、搜索核验、错误身份/职位、招呼去重、每日限额、未知结果不重放及中断恢复。它们不等于真实猎聘/BOSS、真实账号权限或真实招呼发送验收；本次没有向真实候选人发送消息或上传真实简历。
