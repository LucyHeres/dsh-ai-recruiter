# 双入口招聘任务与会话执行面板

来源：用户于 2026-10-16 明确的插件使用场景。0.1.102 已在代码中接入统一任务工具和会话右侧面板；本文区分实现与真实客户端验证，编译成功不代表面板已经完成实机验收。

## 同一能力，两个入口

1. DSH 客户端新发起会话：用户输入招聘任务提示词，由 AI 解析和补齐必要参数，再调用招聘插件。
2. AI 招聘工作台：用户通过表单选择参数、点击操作按钮，直接发起招聘任务。

两个入口必须使用同一套任务服务、平台预设及执行器，不能各自维护一套浏览器操作流程。差异只在参数收集方式和界面展示，不在实际业务行为。

共用内容包括任务 ID、候选人身份、防重复、配额、浏览器执行锁、进度、结果、停止和日志。对同一任务的重连、重复读取或界面切换不重新发起执行，也不重复打招呼或上传。

## 会话右侧精简面板

当新会话实际调起招聘插件执行打招呼或简历上传任务时，在会话页面右侧展示精简招聘执行面板，不要求用户离开会话、手动打开完整工作台才能查看执行情况。

面板定位是任务执行视图，而不是把完整工作台原样嵌入右侧。

### 展示内容

- 任务类型：打招呼或简历上传。
- 任务范围：平台、职位、搜索条件或入库目标等与本次任务相关的摘要。
- 当前状态、当前处理阶段、进度条和完成数量。
- 每位候选人的处理记录、结果和必要的执行动态。
- 失败、待用户处理或执行结果未知时的具体原因。

打招呼和简历入库的完成口径分别展示，不混为“已发送成功”：目标打招呼流程显示“已点击”；简历上传只有取得最终保存回执后显示“已入库”。

### 精简范围

- 不重复完整工作台的任务配置表单，已由会话确定的参数无需再次填写。
- 不默认展示全局连接管理、平台切换、所有历史任务等与当前任务无关的完整工作台功能。
- 有必要的连接或授权阻塞时，展示与当前任务直接相关的提示，不隐藏错误。
- 可复用当前任务的停止和复制日志能力，操作仍指向原任务，不新建第二份执行。

### 会话关联与恢复

- 任务应保留来源入口及所属会话关联，右侧面板只读取当前会话实际触发的任务，不误展示其他会话的任务。
- 执行端是唯一任务状态来源。聊天消息、右侧面板和完整工作台引用同一任务 ID 和持久化记录，不能各自推算成功人数。
- 切换会话、刷新或重新打开面板时恢复读取任务状态，不把重新挂载 UI 当作重新执行指令。
- 任务完成或失败后仍可查看该会话已有记录，不能面板消失后只剩一句无法核对的聊天总结。

## 平台流程

猎聘的推荐打招呼、搜索筛选打招呼、收到简历采集入库，见 [猎聘招聘操作规范](liepin-workflows.md)。这些规则同时适用于会话和工作台入口；其他平台需要各自的真实操作规范，不直接套用猎聘页面结构。

## 当前状态与实施边界

- 当前完整工作台已接入平台预设执行器。
- 会话使用 `ai_recruit_task_options` 读取真实选项和 schema，`ai_recruit_task_start` 启动与工作台相同的任务，`ai_recruit_task_status/stop` 读取或停止当前会话任务。会话身份来自宿主 agent，不接受模型自行填写其他会话身份。
- 客户端通过目标 DSH 0.1.6-alpha.1 的 `sidebarRightTabs`、`sidebar.right.pane.tab` 和会话标题动作挂载精简面板，新任务可自动打开；同一会话重载只读原任务状态。
- 右侧面板与工作台源码已完成接入，仍需在安装后的 DSH 客户端核实挂载、显示、刷新恢复和隔离行为；不要求用户另装独立前端。
- Skill 用于说明任务语义和调用方式，不能替代任务服务及客户端面板实现。

## 最低匹配分（0.1.135）

寻聘设置可填写 0-100 的整数，默认 60 分，对应任务参数 `minimumScore`。0 分表示不按分值排除人选。列表初筛、最终保存和自动打招呼使用同一轮固定值，任务执行中不可更改；对话抽屉与工作台共用此规则。历史任务缺少该字段时按 60 分处理，列表和职位统计按各轮保存的门槛计算，不用当前设置重新筛掉其他轮次的人选。

## 寻聘搜索准备与平台额度（0.1.136）

- 读取薪人薪事职位的结构化工作经验、学历和工作地点，结合本轮明确补充字段生成 `searchFilters`。无论是否自动打招呼均加载平台职位关联。
- 有平台职位选择器时，先选择关联职位，核验当前选中项，不再向主关键词框输入职位名称。没有职位选择器时才核验实际关键词提交。
- 经验、学历、城市必须提供当前快照的已选控件、值或筛选摘要证据。经验桶可扩大覆盖，最低学历包含更高学历，最后仍逐人评分。不支持的字段须引用平台明确限制提示；找不到控件不能算已生效。职位或筛选变更后重新核验。
- 新任务 `limitScope=per_platform`，`limit` 是每个平台独立目标。两平台各5人时总目标10人，低分和重复不占名额。当前平台保存并完成自动招呼后才执行下个平台；历史任务保留原人数口径。
- 未达人数须引用平台明确无更多或无结果提示才能提前完成。登录、页面、身份或招呼校验受阻则停止整轮，保留结果并显示原因，后续渠道标记尚未开始。
- 日志 `sourcing.search_prepared` 记录核验模式及字段结果，`channel_finished` 分别记录渠道数量和目标。模拟测试和构建不代表真实登录平台已验收。

## 职位对接平台（0.1.137）

职位列表读取原接口 `channelType` 中的职位渠道关联，映射为该职位的 `platforms`。卡片显示已关联的可寻聘平台，寻聘设置只展示这些平台并默认勾选；切换职位会清除不再适用的选择，无可用平台时禁用启动并提示先在主系统对接同步。当前执行器支持猎聘（4）和 BOSS 直聘（11），其他渠道不冒充可自动执行的平台。不新增职位列表网络请求，也不从历史任务、平台登录状态推断对接关系。启动前重新读取职位信息并校验所选平台；平台端的具体职位仍由原有 `jobAds` 关联读取及页面选中证据核验。

### 发布渠道完整展示（0.1.139）

此前仅投影成猎聘/BOSS 的 `platforms` 会漏掉主系统“发布渠道”列的内推、门户、猎头及其他渠道。现从同一 `channelType` 保留完整、有序、去重后的 `publishedChannels`（ID 和原始名称），卡片按主系统短名展示；超过三个时通过 `+N` 悬浮气泡查看其余渠道。设置展示完整发布渠道，同时仅将其中支持自动寻聘的猎聘/BOSS作为勾选项。已有其他发布渠道的职位提示“当前发布渠道暂不支持自动寻聘”，不声称没有渠道。前后端均以本次职位的 `publishedChannels` 计算执行范围，不采用历史或过期平台投影。旧执行器须完全退出并重开薪灵后才会加载新包；磁盘安装版本与最近请求日志中的实际运行版本分别核对。

### 五个平台的展示范围与统一标签（0.1.141）

最终产品范围为拉勾（1）、BOSS直聘（11）、智联招聘（2）、前程无忧（3）、猎聘（4）。列表和设置仅展示这五个平台的关联，其他发布渠道保留在原数据中但不渲染。五个平台全部平铺，窄窗口自然换行，不再使用 `+N`。所有平台标签通过 `renderPlatformTag` 和 `air-platform-tag` 的同一组品牌浅色令牌渲染，包括职位卡片、候选人列表/详情、工作台及对话抽屉设置；明暗主题分别有配色。颜色依据主系统本地 `channel-new` 图标：拉勾绿、BOSS青、智联蓝、前程暖红、猎聘橙。展示目录 `RECRUITMENT_PLATFORMS` 与实际浏览器执行器 `PLATFORMS` 分开；拉勾、智联招聘、前程无忧的展示并不等于已实现对应寻聘操作。
