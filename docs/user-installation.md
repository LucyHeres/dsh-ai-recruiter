# 当前客户端安装与使用

## 用户只需安装两部分

1. 从[薪招正式安装页](https://s.xinrenxinshi.com/recruitment/xin-get)安装或更新薪招 Chrome 扩展，保持启用。固定 ID 为 `elbamdfkepfcainfggecfjhahpjjdmdg`；新版包含 Native Messaging 权限。如 Chrome 因新增权限暂停扩展，请按浏览器提示重新启用。
2. 在当前薪灵客户端的插件管理入口，从运营方提供的 npm 版本或 HTTPS 安装包地址安装 dsh-ai-recruiter，按客户端要求重启。
3. 打开已登录的目标网页，直接在 DSH 提出任务，例如「读取当前网页上的候选人信息」。本机桥接就绪后会主动通知扩展连接，界面显示「已连接」后即可使用。

无需浏览器控制账号、终端命令、额外 Node/Python、配对文件或连接链接。DSH 首次加载自动注册本机桥接，扩展在后台获取本机连接配置。两端安装先后均可；桥接未就绪时扩展先快速重试，连续失败后每分钟再发现。桥接通道建立后，用户发起连接无需等待分钟级探测。

适用边界：DSH 与 Chrome 在同一电脑、同一系统用户下运行，扩展 ID 与上述固定 ID 一致。当前宿主基线为薪灵 2.0.18 / DSH 0.2.1-rc.2 / Cordis 4.0.5，旧版客户端不再支持。实现包含 macOS、Windows 和 Linux 用户级注册；尚未完成三平台真实 Chrome 验收，不把代码分支存在当作平台验证通过。

## 浏览器操作与招聘业务

- 网页读取、点击、输入、导航、滚动、下载：扩展作为通用浏览器工具，不需要薪人薪事业务登录。
- 招聘入库：需要客户端提供薪人薪事授权。DSH 插件负责上传地址、上传文件、解析、查重和保存；扩展只抓取文件、返回受当前任务限制的分片。
- 原始文件只在 DSH 内存处理，不放进模型输出或本地任务记录。插件只记录阶段及业务 ID。结果未知时停止自动重试，先核对业务状态。
- 登录招聘网站使用 Chrome 自己的登录状态。业务账号登录与本机桥接是两件事。

## 连接异常

让 AI 检查 ai_recruit_help：nativeConnection.registered 表示注册成功，browser.ready 才表示扩展已连通。注册成功仍未连接时，核对扩展已启用、固定 ID 和两端是否在同一系统用户下。

企业策略或文件权限阻止 Native Messaging 时，才使用备用方式：在 DSH 要求生成连接链接，在 Chrome 中打开并在扩展设置页允许。五分钟内一次有效，不要分享。高级设置中的文件导入保留给人工排障。

已有本地连接或其他浏览器任务正在执行时，不更换配对、不抢占任务。升级保留已有配对；若主动更换本机配置，需结束旧任务后重新配对。

## 升级、卸载与运营分发

DSH 插件与 Chrome 扩展分别升级。插件卸载/停用时撤销本次注册的原生桥接，保留用户配置与业务记录；浏览器网关仍遵循原有空闲退出机制。异常退出可能留下注册文件，下次加载更新注册；不要删除源码或安装包后把残留路径当作已安装服务。

运营方发布预编译 npm 包或固定版本 HTTPS tgz，保留旧版本地址，不向客户分发开发机 file: 路径。扩展在 xinzhao 工程通过 npm run pack 独立打包、保持 manifest.key；DSH 包不附带扩展 ZIP。私有部署的文件服务可通过 fileUploadOrigins 配置精确 HTTPS origin。

上线人工验收：全新安装自动发现、没有业务授权也能操作网页、有业务授权的文件上传与入库、重启重连、任务释放、升级和卸载。当前未运行测试、未进行真实浏览器或真实入库验收，尚未发布到正式渠道。

## 职位业务查询（0.1.15）

`ai_recruit_context` 的 `recruitment_getMyJobList` 与 `recruitment_getJobDetail` 已由插件直接调用业务接口，复用现有 xrxsAuth，不要求会话另行开放这两个 MCP 工具。参数结构通过 `ai_recruit_help.contextSchemas` 提供。列表支持 keyword、hireStatus（默认 0）、offset（默认 0）、limit（1–100，默认 50）；详情传 jobId。

列表读取 `/recruitment/service/ajax-extension-get-init` 的 positionNames，在插件内筛选和分页，保留真实职位 ID，范围与薪招初始化选项一致；详情使用 `/recruitment/service/ajax-get-job-detail`。同名职位不能自动选择第一项。其余 context 操作仍由宿主 MCP 提供，help 的 source 字段会明确标明。

## 0.1.15 调用效率改进

新增快照、点击、输入三个独立工具；通用调用保留。插件与内置 MCP 在发出操作前校验 schema，错误返回字段路径和约束。批量动作的 schema 补齐子动作结构、定位条件、documentId 和 maxWrites；重复动作 ID 被拒绝。每个会话同一工具的相同失败参数不重复发送，允许一次修正尝试，之后冷却两分钟并提示停止排查。限制在进程内保存，仅存参数哈希，不保存输入文本；重启会清空，不能代替业务幂等或未知结果核对。

## 工作台扩展安装检测（0.1.51）

顶部卡片单独显示扩展安装状态。未检测到时点击“去安装薪招”，入口为正式环境 https://s.xinrenxinshi.com/recruitment/xin-get；安装并启用后点击“重新检测”，再“连接浏览器”。无法确认时也提供安装指引，并保留连接按钮。

扩展已认证连接时直接确认安装；未连接时只读 Chrome、Chromium、Edge 默认用户目录及浏览器配置中的扩展记录，每 15 秒更新一次，手动重检刷新缓存。已安装与已连接分开显示，停用或尚未连接不判为未安装。自定义目录、权限限制或配置异常可能无法确认；在其他浏览器配置安装时需使用该配置连接。检测不会修改浏览器设置。
