# 猎聘招聘操作规范

来源：用户于 2026-10-16 描述的真人操作流程。0.1.102 按本规范接入统一任务和平台预设，搜索条件由任务内 AI 设置、代码核对后连续执行；仍需真实客户端和平台验收。仅适用于猎聘，不推断 BOSS 的页面和操作方式。

## 执行方式

### 两种触发入口

完整双入口和新会话右侧精简执行面板的目标要求见 [双入口招聘任务与会话执行面板](recruitment-entrypoints.md)。

- 新会话提示词：AI 解析用户意图、职位、筛选条件、数量和入库目标，补齐必要信息后提交结构化任务。
- AI 招聘工作台按钮：表单直接提供上述结构化参数，不要求用户再输入提示词，也不重新请求 AI 理解已明确的设置。
- 目标是两个入口调用同一套招聘任务执行器与平台预设，共用去重、配额、执行锁、停止、日志和任务记录；不能只在聊天 Skill 中描述流程，而让工作台继续走另一套逐步规划。
- 0.1.102 会话统一任务工具和工作台均通过 `GreetingAgent` / `runResumeAgent` 接入 `runRecruitmentAgent` 平台预设；单独调用通用浏览器工具不会自动创建带进度面板的招聘任务。
- 现有工作台打招呼对应流程一，简历上传对应流程三。流程二的搜索筛选任务需要会话任务参数或工作台新增对应筛选入口，不能把现有推荐打招呼按钮当作已经支持搜索。

### 执行分工

- 本文记录业务流程；高频操作由招聘插件中的平台预设执行，不依赖 AI 每点击一次就重新规划。
- AI 负责理解用户任务、将自然语言条件对应到页面实际筛选项，以及处理预设不认识的页面状态。条件和路径明确后，交回预设连续处理。
- 薪招扩展保留通用浏览器和附件采集能力；职位、筛选、候选人、沟通状态等平台语义留在招聘插件。
- 数量及点击间隔沿用任务设置和现有执行规则。本规范取消发送结果核实等待，不等于取消全部点击间隔或允许无限发送。

## 一、按职位推荐人才打招呼

用户意图示例：“去猎聘自动跟某职位的候选人打招呼”。

1. 进入人才推荐页。
2. 选中用户指定的职位，确认页面当前选中的是目标职位；同名且无法可靠区分时，不任意选择。
3. 读取推荐候选人列表，将候选人和其列表项内的沟通按钮对应起来。
4. 按按钮状态分支：
   - `立即沟通`：尚未打过招呼，可以执行单人平台默认招呼。
   - `继续沟通`：已经打过招呼，必须跳过，不得再次点击沟通。
   - 其他按钮或状态：不能擅自当作 `立即沟通`，需要页面依据或后续明确适配。
5. 点击前保存当前候选人的操作记录。收到明确的点击执行成功回执后，记录为“已点击”，立即进入下一人的定位，不再等待成功提示、按钮变色或 AI 核实送达。
6. 达到任务人数或列表明确耗尽时结束。需要翻页或滚动时，依据实际列表控件继续，不猜地址或盲点背景元素。

完成口径：点击执行成功，不是平台消息送达。点击被拒绝、尚未派发不能计入“已点击”；超时或执行结果未知时不算成功，不自动重发。页面 `继续沟通` 状态和已有操作记录都用于防重复。

## 二、搜索筛选人才后打招呼

用户意图示例：“去猎聘筛选北京的年龄 35 岁以下的工作经验 5–10 年的 java 开发工程师简历，并打招呼”。

1. 进入搜索人才页，不走人才推荐页代替搜索。
2. 从用户原话提取城市、年龄、工作经验、职位关键词等条件，保留原始条件供核对。
3. 根据页面实际提供的筛选项和搜索框设置条件，再执行搜索。示例条件是北京、35 岁以下、5–10 年工作经验、java 开发工程师。
4. 页面筛选范围或边界不能准确表达用户要求时，不静默放宽条件；明确指出差异，必要时由用户选择处理方式。
5. 在搜索结果中按每个列表项的沟通按钮处理：只点击 `立即沟通`，跳过 `继续沟通`。
6. 点击完成口径、防重复、数量及异常边界与流程一一致。搜索条件已经建立后，不逐人重新请求 AI 解释相同条件和按钮。

搜索关键词、平台当前发送职位和薪人薪事职位是不同概念，不能直接互相替代或把关键词当作职位 ID。

## 三、收到简历批量采集并上传薪人薪事

用户意图示例：“去帮我拿到发了简历的候选人的简历，并上传到薪人薪事”。

1. 进入人才管理页，选中 `收到简历` tab。
2. 用户指定平台职位时，按该职位筛选；未指定时，可以不设置平台职位筛选，不擅自缩小范围。
3. 读取收到简历列表，点击候选人进入详情。
4. 在当前候选人详情里找到 `附件简历` 区块，再找到该附件上的真实 `下载` 按钮。附件区块本身、简历全文或其他候选人的控件不能代替下载按钮。
5. 下载按钮在视口外时，先滚动对应容器，再读取新快照和新引用。前景弹窗中的按钮不能与背景列表混配。
6. 通过现有附件采集流程取得完整原始文件，再调用薪人薪事的上传、解析、查重和保存流程；不把 HTML、JSON 或页面文字伪装成附件。
7. 以薪人薪事最终保存回执判定“已入库”，不能沿用打招呼的“点击就完成”口径。
8. 当前候选人处理结束后，关闭详情或返回收到简历列表，继续下一位，直到达到任务人数或列表明确耗尽。

平台列表的职位筛选可以不设置；薪人薪事入库要求的目标职位、来源渠道、入库位置等参数仍须来自用户选择或真实业务选项，不能猜测。没有附件或存在多个无法区分的附件时，说明原因而非下载任意文件。已有成功或结果未知的入库记录不能自动重复提交。

## 0.1.102 实现与待验证边界

- 猎聘预设只匹配 `立即沟通`，跳过并阻止点击 `继续沟通`。
- 默认单人招呼点击成功后自动结束当前人，界面显示“已点击”，不伪造“已送达”或 `confirmedAt`；普通输入失败及未知执行仍受原保护约束。
- 搜索模式使用真实观察中已出现的 `/search` 入口，提供条件参数和确认工具，未执行搜索或条件缺少生效证据时禁止选择和发送。
- 收到简历预设核对 tab、支持独立的可选平台职位筛选、按详情弹窗定位下载按钮、滚动后用新引用继续，并从已知详情返回列表。
- 点击 `立即沟通` 后若出现额外推荐、付费、确认或其他弹窗，其具体处理尚未由用户描述；不能擅自批量开聊、付费或重发。
- 页面 URL、DOM 结构、筛选控件取值等技术定位以实际页面观察为准，不由本文虚构。本文不构成真实平台运行速度或入库成功的验证。
