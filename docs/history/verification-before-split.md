# 验证范围

目标来自本机薪灵 1.0.2 安装包：DSH/tools/system-prompt 0.1.6-alpha.1、Cordis 4.0.2。内置 XRXS 连接插件 0.2.2，工具契约来源为 2026-10-11 实时 tools/list，服务端 xrxs-mcp 0.4.0。`test/mcp-contracts.json` 保存相关工具 schema，不含凭据或用户业务数据。

AI 招聘助手另有两条契约来源，均已在本地代码库核对：浏览器侧为薪招扩展网关的 `tools/browser-agent-gateway/mcp-server.js`（19 个 capability，stdio JSON-RPC）；入库侧为薪人薪事招聘内部业务接口，参考实现在 `unicorn-recruitment/src/module/xinzhao/`。

本项目不使用先前审批插件代码或对官方 Desktop 0.2.x 的验证结果；审批插件已停止开发。

## 验证层次

1. TypeScript 检查：目标版本依赖下的三个包。
2. 实际 Cordis/ToolRuntime + 模拟 MCP：排程、缺失字段、不可行与预算耗尽、生成文件、模板复用、权限链、写入前摘要校验、逐人写入和回读、丢失响应后的停止/对账、不可识别回读、引用校验、候选人隔离、卸载取消。
3. 招聘助手专项：候选人卡片解析（真实猎聘页面文本）、业务接口参数白名单与失败码映射、凭据头组装、上传地址两种返回形态、真实 Cordis 挂载下的 scan/capture/ingest/result、无授权时插件仍挂载且入库明确失败、上传结果未知后停止且不重放、上传地址过期后恰好重取一次、网关错误码原样上报（BUSY 不被降级）、旧信封形态兼容。
4. 打包检查：入口、类型、bundle patch、locale、共享编译文件、peer/dev 一致、发布内容不含 node_modules 或测试数据。
5. 独立完整 DSH Web Host：临时 profile 安装三个 tgz、注册工具、模拟编排/创建/回读/准备包渲染、招聘助手对假网关完成 auth_check、scan 与 capture，卸载后重启确认工具消失。
6. 真实网关联调（只读）：用本插件的 MCP 客户端直连本机运行的薪招网关，走完 initialize → tools/list（23 个工具）→ browser_status → browser_list_tabs → browser_snapshot，并对真实猎聘「收到简历」页面完成一次 scan。

2026-10-11 验证结果：TypeScript 检查及编译通过；29 项测试全部通过（含 13 项招聘助手专项）。三个发布包的入口导入和内容检查通过。临时完整 Web Host 的安装、模拟业务调用、卸载及重启检查通过。真实网关只读联调通过：`browser.available=true`、工具数 23、命中已登录的猎聘标签页，`scan` 在真实页面上解析出 3 位候选人（与同一次快照的原文一致；其中一位无「先生/女士」故无姓名，属已知局限）。

### 真实网关联调暴露并已修复的契约差异

只有连真实网关才会发现：官方 `mcp-server.js` **已经把网关信封解包**，成功时 `content[0].text` 就是 `data.output` 本身，失败时（含 `data.status !== 'succeeded'`）折叠成 `isError` + 一行错误文本。最初的实现按「透传 `{ok,data:{status,output}}`」建模，导致真实环境下成功的调用被判成 `failed`；同理，最初的测试替身也复刻了错误的形状，所以单测全绿也没能发现。现已按真实契约实现并保留对旧信封的兼容，且测试替身改为复刻真实形状，避免再次出现「测试与真实契约同时错」。

真实联调同时确认：网关冷启动需要等待扩展连接（本机实测约 47 秒），`browser_status` 会给出 `state/ready/executionOwner`，可用于判断是否可安全发起调用。

## 2026-10-12 鉴权修复验证

对照本机 `dsh-xrxs-lingting@0.4.11`、`xrxs-dsh-auth@0.4.2` 已发布实现，以及 `unicorn-recruitment/src/module/xinzhao/utils/login-session.ts`、招聘后端 `ThirdPartyController` 和 `ExtensionLoginInterceptor` 核对鉴权流程。系统会话调用薪招初始化接口返回 `code=318241003`；同一会话换得薪招 token 后，初始化返回 `status=true, code=0`。普通系统登录与薪招专用 token 是两个步骤。首次验证使用过 browser 槽，会更新该账号的浏览器登录票据；后续真实插件验证与正式实现均使用 pc 槽。

修复后的插件在真实 Cordis/ToolRuntime 中挂载，使用薪灵当前授权服务连续两次执行 `ai_recruit_auth_check`。两次均返回 `authenticated=true, recruitmentReady=true`，业务登录、上传地址、薪招初始化三项均成功。只输出检查结果，不输出 token、Cookie、sessionId、公司详情或上传票据；没有请求模型或上传/保存任何候选人简历。换票使用桌面 `pc` 登录槽，服务端会撤销该账号此前的同槽 token；插件共享内存缓存，避免每次工具调用重新换票。重启或同账号其他桌面薪招登录会要求重新换票。

本次 TypeScript 检查和编译通过，41 项行为测试通过，覆盖换票请求头、并发换票共享、公司/环境切换、失效 token 不重放写请求、取消、脱敏诊断，以及上传→解析→查重→保存和未知结果保留。三个包的发布内容及入口检查通过；临时完整 DSH 0.1.6-alpha.1 Web Host 的安装、auth_check/scan/capture、卸载和重启确认通过。0.1.1 已安装到薪灵 desktop profile，安装代码与 tarball 一致，仅更新招聘助手依赖，cordis.yml 与 cordis.patch.yml 原样保留。正在运行的薪灵仍需重开以加载新版。

## 真实业务联调仍需核对

- MCP 工具当前可见性不等于当前公司每项业务都可调用；还需在具体账号、职位、轮次和员工权限下核对。
- 日程读取器支持 `interviewerSchedule[].scheduleList[]`，以及 CLI 对这个结构的数组/按日包装。缺少面试官或未知结构不会默认空闲。
- 冲突结果需明确 `timeConflict=0`；未知结构停止。日期严格使用北京时间，跨天场次不创建。
- 回读需有唯一匹配的轮次 ID、轮次设置 ID、开始时间、时长、面试官集合。字段缺失或不一致标为 unknown，不把成功响应当成全部业务成功。
- 当前 MCP 日程 schema 同时要求日期范围、时刻、时长，虽然部分描述说某些字段不需要；插件按严格 schema 全部传入。
- 未验证真实模型自主调用，未创建真实面试，未发送任何真实通知。不得声称生产端到端已完成。
- 模板仅保存轮次和规则；产物留在用户本机。联系方式与明显人口属性按字段名和字段标签移除，但这不代替企业级 DLP；不要将生成材料自动外发。

## AI 招聘助手尚未验证的部分

以下每一条都**没有**被验证，不得据此宣称已可用：

- **未对真实猎聘/BOSS 页面跑通端到端采集。** 只读部分已真实联调通过（工具发现、快照、候选人解析，见上）；但本工程**未用真实候选人执行过 `acquire_file`**，也未把任何简历上传到生产文件服务。`capture` 与 `ingest` 只在假网关 + 打桩 fetch 下验证过行为契约。
- **文件服务上传仍未实测。** 真实上传地址获取及 HTTPS 校验已通过；追加 `is_permanent=true` 使用 URL 查询参数构造，在测试中验证。未将真实文件交给扩展上传，因此不能声称真实文件服务完整链路已通过。
- **解析/查重/保存未在生产调用。** `resumeBodyType=2`（文件 Key）由后端枚举 `EResumeBodyType` 与 `ExtensionBusinessImpl` 的 `FILE_KEY` 分支佐证，但未实测生产返回。
- **候选人解析是尽力而为。** 入职期望字段来自页面文本正则：姓名会被拆成姓（"曹先生" → "曹"），无「先生/女士」的卡片取不到姓名。`candidates` 只能作为提示，入库前必须回到 `text` 与页面核对。
- **未验证长列表行为。** 整页文本会被扩展截断（约 4600 字），逐屏滚动与分页未做验证。
- **上传回执字段名存在不一致证据。** 本地 Java 代码中 `data.key` 与 `data.file_key` 并存，业务编排读取浏览器网关标准化后的 `fileKey`；生产文件服务经网关转换的回执仍需真实上传验证。
- **文件服务非 exactly-once。** 上传成功但回执丢失时可能产生孤立文件；插件按「结果未知即停止且不重放」处理，并要求入库侧幂等，但这只在本地测试中验证过行为契约，未验证真实故障场景。
- 凭据通过宿主 `xrxsAuth` 在内存中取得和使用；不直接读取凭据文件，不保存或输出 Cookie、token 或会话标识。本地只记录阶段与 ID，不保存简历原件。

## 2026-10-12 通用浏览器操作扩展

0.1.3 增加动态浏览器工具发现与调用，去掉招聘助手的打招呼、发起沟通和创建会议固定禁令。模拟网关验证非招聘域名导航、输入沟通内容、点击发送、执行新增 capability、透传 policy，浏览器操作在未挂载 xrxsAuth 时可用。未知工具在调用前拒绝；BUSY 和 RESULT_UNKNOWN 原样上报且不自动重试、不释放他人任务；取消后的结果保持未知，卸载后工具消失。

真实网关验证仅执行 initialize 与 tools/list，不获取浏览器执行权、不点击页面、不发送消息。此版本没有对真实网站执行沟通或表单提交；新增能力的可用范围取决于当前网关与扩展。

本次 TypeScript 检查与编译通过，48 项测试全部通过；真实网关通过新增 DSH 工具发现 23 个工具及其输入 schema，包括点击、输入、导航、批量动作和流程开始/结束。未执行任何真实浏览器动作。
